# 기기별 Drive 자료와 담당자

0.4.16부터 중앙 관리의 **기기별 강의자료 Drive**에서 공용 소유 계정·기기 폴더 ID·자료 담당자 Google 이메일을 저장한다. 담당자는 먼저 해당 호실을 제어할 수 있는 중앙 관리자 또는 호실 담당자로 등록돼 있어야 한다. 기존 관리자 역할은 변경하지 않는다.

연결된 PC에 기존 인증 USB bridge로 설정을 전달한다. PC의 등록 호실과 일치해야 하며 기존 기기 폴더·소유 계정은 고정한다. 현재 각 호실의 설치 PC 한 대를 기기 단위로 취급하므로 교체 PC도 같은 호실 폴더를 사용한다.

PC에서 공용 계정으로 Drive 연결을 승인한다. 앱은 소유자를 확인한 뒤 다른 사용자·그룹·도메인·공개 권한을 제거하고 지정 담당자를 읽기 전용으로 설정한다. 알림 이메일은 발송하지 않는다. 공용 소유 계정은 소유자 접근을 유지한다. 상속된 외부 권한은 자동으로 부모 폴더에서 제거하지 않고 작업을 중단한다. 따라서 공용 상위 폴더는 외부에 공유하지 않는다.

실제 Google 권한을 다시 조회해 소유자+지정 담당자만 남았는지 확인한 뒤 업로드·바로가기를 허용한다. 담당자 미정은 업로드하지 않으며 소유자 전용이다. 담당자 브라우저의 Google 계정 선택과 최종 접근 판정은 Google Drive가 수행한다.

Drive 구조는 `강의자료/기기 폴더/YYYY-MM-DD 원래파일명`이다. 날짜별 하위 폴더는 만들지 않는다. 로컬은 PC별 `문서/SilentStream/USB 자료/YYYY-MM-DD/자동 생성 파일명`을 사용하며 7일 후 정리한다. 이전 공통 폴더의 파일은 어느 기기 자료인지 추측해 이동하지 않는다.

USB 자료 탭의 Drive 링크는 담당자 본인에게만 내려주며 PC 오프라인에서도 이미 검증된 링크를 열 수 있다. 관리자가 모든 PC를 제어할 수 있어도 다른 담당자의 Drive 읽기 권한이 자동으로 생기지는 않는다.

담당자 변경·해제는 PC 공용 계정 연결과 Google 권한 반영 전까지 대기 상태다. 해제 요청만으로 이전 담당자의 실제 접근이 즉시 사라졌다고 표시하지 않는다. 기존 유효 담당자의 중앙 계정 삭제·호실 제외는 Drive 권한 해제 확인 뒤에 허용한다. 실패는 버전별 한 번 기록하고, PC의 재시도 또는 중앙의 명시적 재저장 후에만 다시 시도한다. 백그라운드 OAuth 창·AI 작업은 없다.

Google 권한은 변경할 때와 각 업로드 전에 검증한다. 웹의 확인 상태는 PC가 마지막 보고한 결과이며 Google에서 수동으로 바꾼 설정을 실시간 감시하는 상태는 아니다. 외부에서 폴더/하위 파일에 직접 별도 공유를 추가하지 않는다. 실제 OAuth·파일 업로드는 모의 시험과 별도로 현장에서 검증한다.

근거: [Google Drive 공유 권한](https://developers.google.com/workspace/drive/api/guides/manage-sharing), [읽기 권한 생성과 알림 설정](https://developers.google.com/workspace/drive/api/reference/rest/v3/permissions/create).
