# 수업 종료 후 라이브 재생목록 편입

## 현재 서버 방식

기본 편입 담당은 Cloudflare 서버다. PC의 라이브/재시작 이력을 받는 즉시 영속 예약을 저장하고 17:25 이후 방송 종료·아카이브 준비를 확인한다. 등록 메시지보다 전원 차단이 빨랐던 경우에 대비해, 연결된 채널의 최근 방송 중 SilentStream 호실·날짜 형식과 일치하는 방송도 평일 17:25에 확인한다.

서버의 YouTube 편집 권한은 `/control/youtube`에서 관리자만 연결한다. 갱신·접근 토큰은 별도 서버 비밀키의 AES-GCM으로 암호화해 저장한다. 토큰·기기 식별 정보는 재생목록 페이지에 전달하지 않는다. 서버 재시도·실행 선점·실제 재생목록 구성원 조회로 중복 삽입을 방지한다. 실제 송출이 진행 중인 방송은 끝내지 않으며, 오래 접속하지 않은 PC의 방송도 YouTube 스트림 비활성을 두 번 확인한 뒤에만 종료를 시도한다.

PC의 기존 편입 엔진은 `youtube.useLocalLiveReplayRecovery=true`일 때만 실행하는 별도 로컬 대체 경로로 남긴다. 기본값은 false다. 서버가 맡는 동안 로컬 편입을 동시에 켜지 않는다.

## 로컬 대체 경로

- 한국 날짜의 마지막 수업이 끝난 뒤, 그 날 시작한 라이브를 같은 날짜·호실의 재생목록에 넣는다. 현재 고정 시간표는 평일 17:25 종료다. 주말에는 자동 편입하지 않는다.
- 방송 중에는 넣지 않는다. YouTube의 `complete`, 실제 종료 시각, 영상 처리 상태 `processed`를 확인한다. 다시보기 처리 지연·인증/통신/API 실패 시 대기 기록을 유지한다.
- 앱 실행 즉시 누락분을 확인하고 이후 최대 15분 간격, 마지막 교시 종료 경계에 확인한다. 재생목록 등록 성공 후에만 완료로 기록한다. 하루 중 여러 번 방송했으면 각 영상을 편입한다.
- 방송 시작 단계에서 영상ID·호실·시각을 `live_replays.json`에 원자 저장한다. 대기 항목은 최근 50개 링크 제한으로 지우지 않는다. 완료 항목만 최근 50개를 유지한다. RTMP 주소·키나 OAuth 토큰은 이 파일에 넣지 않는다.
- 전원 차단으로 종료 처리를 못한 방송은 다음 실행 때 YouTube에서 상태를 확인하고, 이전 실행의 `live`/`testing` 방송만 종료 전이를 시도한다. 현재 실행에서 송출 중인 방송은 종료하지 않는다. 종료 전이 다음 검사에서 처리 완료를 확인한다.
- 재생목록 등록 뒤 완료 표시 전에 꺼져도 기존 등록 이력을 확인한다. YouTube 삽입 뒤 로컬 기록 전에 꺼져도 다음 실행에서 실제 재생목록 구성원을 조회하므로 같은 영상이 다시 삽입되지 않는다.
- 과거 스키마의 호실 없는 링크는 해당 PC의 현재 호실로 해석한다. 호실이 기록된 항목은 다른 호실에 편입하지 않는다. 한 회차 최대 32개 대기 항목을 순환 처리한다. 항목별 15초 제한, 회차 2분 이후 추가 처리 중단으로 오래 걸리는 작업은 다음 회차로 넘긴다.

PC가 꺼져 있는 동안 이 작업은 실행되지 않는다. 종료 시각 전에 꺼졌다면 다음 앱 실행과 네트워크/인증 복구 뒤 처리된다. 전원이 꺼진 상태에서도 당일 처리를 보장하려면 서버에서 방송ID·재생목록ID·실행시각을 보관하고 해당 YouTube 계정의 별도 OAuth 위임으로 처리해야 한다. 현재 제어 서버의 Google 로그인은 YouTube 편집 권한이 아니며, 이 변경은 PC의 토큰을 서버에 올리지 않는다.

검증: 전원 차단 후 다음날 복구, KST 날짜, 17:25 전후, 진행 중 방송, 처리 지연, API 실패, 부분 성공, 중복, 호실/주말 분리, 대기 기록 보존을 자동 검사한다. 실제 PC 종료·운영 방송 종료·YouTube API 쓰기는 검증 중 실행하지 않는다.

API 근거: [방송 상태 전이](https://developers.google.com/youtube/data/live/reference/rest/v3/liveBroadcasts/transition), [방송 종료 시각](https://developers.google.com/youtube/data/live/reference/rest/v3/liveBroadcasts#snippet.actualEndTime).

## PC 전원과 독립적인 서버 예약 대안 — 2026-10-27 검토

기존 Cloudflare Worker의 Durable Objects Alarm으로 PC와 독립적인 예약을 구현할 수 있다. 이 절은 검토 결과이며 서버 예약·권한 연결·배포를 완료한 기록이 아니다.

1. PC가 방송을 만들 때 호실·KST 날짜·방송ID·대상 재생목록·마지막 수업 종료 시각을 서버의 영속 대기열에 등록한다. 종료 직전에만 등록하면 갑작스러운 전원 차단을 견딜 수 없으므로 시작 시 등록하고 필요 정보가 준비되면 갱신한다.
2. 서버가 17:25 이후 방송 종료·다시보기 처리를 확인하고 편입한다. 현재 앱은 방송 자동 종료가 꺼져 있으므로, 전원 차단 후에도 YouTube에 live로 남을 수 있다. 이를 종료하려면 해당 방송의 바인딩된 스트림이 실제로 inactive인지도 확인해야 한다. PC의 마지막 접속 시각만 보고 방송을 끝내지 않는다.
3. 방송 중·처리 지연·통신 실패는 영속 상태로 남기고 다음 알람으로 넘긴다. 동일 호실/날짜/영상의 완료 상태와 실제 재생목록 구성을 확인해 중복을 방지한다. 알람은 최소 한 번 실행 보장이므로 중복 실행 가능성을 전제로 한다. 알람 시간은 정확한 초 단위 실행을 보장한다고 설명하지 않는다.
4. 서버 위임이 확정된 작업은 서버가 편입을 전담한다. 등록 응답이 유실된 상태를 로컬 작업으로 즉시 되돌리면 양쪽이 동시에 삽입할 수 있으므로 서버 상태 조회로 소유권을 먼저 확정한다. 기존 로컬 재시작 복구와의 경합을 설계해야 한다.

서버에는 대상 YouTube 채널의 OAuth 편집 권한과 갱신 토큰을 별도로 연결해야 한다. 기존 관리 웹의 Google 로그인은 openid/email/profile이며 YouTube 편집 권한이 아니다. PC의 DPAPI 암호화 토큰을 파일 복사해 해결할 수 없으며, 새 동의·안전한 서버 저장·채널별 연결 확인이 필요하다. 토큰을 GitHub나 프런트엔드에 넣지 않는다.

근거: [Cloudflare Alarms의 영속 예약·재시도](https://developers.cloudflare.com/durable-objects/api/alarms/), [YouTube 재생목록 삽입 권한](https://developers.google.com/youtube/data/reference/rest/v3/playlistItems/insert).

## 서버 구현과 실행 환경 검증 — 2026-10-27

위 서버 대안은 현재 구현·배포됐다. 관리자 `/control/youtube?room=m112`에서 실제 강의 채널을 연결하면 영속 큐와 알람이 17:25 이후 편입을 처리한다. 호실별 채널 소유 확인·암호화된 갱신 토큰·실제 재생목록 중복 확인·일일 방송 검색을 사용한다. 서버 연결 전에는 편입 완료를 보장하지 않는다.

서버의 native `fetch`를 클래스 속성에 그대로 저장하면 Workers에서 잘못된 `this`로 호출되어 `Illegal invocation`이 발생한다. 전역 호출을 감싼 함수로 이를 수정했다. Node 검사와 별도로 실제 workerd에서 채널 확인·토큰 암호화·갱신을 검증하는 `test/runtime/youtube-runtime.test.mjs`와 GitHub 검사 작업을 추가했다. 테스트의 외부 통신은 가짜 YouTube Worker에만 연결하며 실제 자격 증명이나 운영 영상은 사용하지 않는다.

실행 환경 근거: [Cloudflare의 Illegal invocation 설명](https://developers.cloudflare.com/workers/observability/errors/#illegal-invocation-errors).
